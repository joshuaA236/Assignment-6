(2) In order to prevent data races, I use the scalar multiplication example from this weeks reading. In 14.3, we learned that, "In the scalar multiplication program, for instance, each element of the array is entirely independent of all the others, making it unnecessary for the threads to share data." I took that idea and appleid it here. Each thread is given its own argument, worker_arg, and processes its own section of data. Since each thread writes only to its own results, (args[i].count and args[i].result), no threads overlap and write to the same memory location.
